# 卷首字节稳定性 —— 前缀缓存不再被「记忆库」打穿（2026-09-18 立项）

> **决定先行**：现状「重启 + 记忆库有变动」= **整卷重算**（实测一次 34.7 万 token 全价，
> 首请求命中率 99% → 0.6%）。**「把记忆库段挪到卷首末尾」是无效修法**——前缀缓存命中 =
> 与新请求的**最长公共前缀**，而对话在卷首之后：卷首任一字节变化，该点之后的整个对话全灭。
> 真正的修法只有一条主干：**让易变内容离开卷首前缀**（裁定见 §3）。
>
> 状态：**Proposed·Draft（未开工）** · 证据：2026-09-18 真机（卷 7）· 邻接已修：合卷丢账本
> = `fb63c94d`（同批侦查发现，与本文病灶不同源）。

## 1. 病灶（实测证据，可复算）

- 2026-09-18 10:23:00 首个请求：`prompt=349,407 / hit=2,176`（**0.6%**）——服务端只认回前
  34 个 64-token 块。其后 10 次请求 99.8–99.95%。
- **不是空闲过期**：同日 00:32 空 54 分钟 → 99.1%；09-16 空 9 小时 → 99.3%；09-15 空 18 分钟 → 99.9%。
- **是卷首字节变了**：卷 7 两次 `session/reset`（`.lantai/sessions/7.ndjson` seq=1 @08:32:11 /
  seq=827 @10:22:09）的卷首 system 文本，**前 4,691 字符逐字节相同、尾部 1,554 相同**，中间
  **+401 字符 = 两条 09:00 写入的记忆条目**（`asset-delete-channel-missing` /
  `image-pipeline-live-shell-stamp-fixed`）。
- 卷首按卷打开时快照（非每请求重读）——实测：09:00 写完记忆后，当轮 09:43–10:00 的请求仍
  99.9%；只有**重启**（10:22:09 重装卷首）才变字节。
- 机理：前缀缓存命中 = 新请求序列与缓存序列的最长公共前缀。卷首在对话之前 ⇒ 卷首变一字节
  ⇒ 其后**整个对话**（卷 7 = 34 万 token）按未缓存计费。
- 与既有纪律冲突：工具面早有「**保持 tools 段逐字节稳定**，DeepSeek 前缀缓存才能跨用户消息命中」
  （`agent/agent.ts` `_schemaSelector` 注）；记忆库段是同一纪律在卷首的漏网。

## 2. 为什么不采纳「挪位序」（纠错留痕，勿再提案）

有目录面段序 = `identity → env → model-identity → memory → claude-md`（`composition/prompt-sections.ts`）。
把 `memory` 移到 `claude-md` 之后：分叉点从 ~2.5k token 挪到 ~9.6k ⇒ miss 从 347k 降到 340k，
**省 2.8%**，性质不变。已验算。

## 3. 两个真候选 + 裁定

| 案 | 语义 | 代价 | 判 |
|---|---|---|---|
| **A 卷首记忆随卷冻结**（重开沿用该卷诞生时那份） | 旧卷看不到新记忆（注：运行期内本来就是冻结的——记忆更新走 `notifyMemorySaved` 通知 + memory 工具按需查） | 需把「该卷用的记忆文本」记进日志头（`presetId` 同款先例）+ 重开时回灌装配面；**不动段表、不动基线** | 备选（便宜、见效快） |
| **B 记忆改走对话通道**（起卷注入一份记忆快照消息；此后变更只在**对话尾部**追加更新条目；卷首不再含记忆段） | 记忆始终最新 **且** 缓存跨重启存活 **且** 无每请求税 | 动段表/组合寻址面 + 装配面 + 基线重录（BCR + 双轨） | **推荐（正解）** |

裁定：**按 B 落地**；A 只作为「B 之前要不要临时止血」的备选，不单独做。

## 4. 落地步骤（B）

1. 段表摘除 `memory` / `memory-brief`（`composition/prompt-sections.ts` 与 `firstPartyPromptSections()`）
   ——卷首只剩稳定段；`PromptSectionContext.memorySection` 随之退役。
2. 记忆注入改走对话通道：起卷注入一条**记忆快照消息**（持久化进事件日志）；此后变更走**既有**
   `notifyMemorySaved` 追加更新条目（该路已在，只需承载内容）。
3. 装配面同步：`runtime.ts` 的 `buildSystemPrompt(..., memSection, ...)` 入参收口 +
   `workspace.setupAgent` 的 `memoryManager.loadPromptSection()` 改投递到卷首注入点。
4. 守护测试（从用户操作序列新写）：① 起卷注入一次且落日志；② 记忆变更只追加、不重写卷首；
   ③ 卷首文本逐字节不含记忆段。
5. **BCR**：`docs/archive/agent-core-convergence/baseline-change-request.md` 追加一条
   （`phase-0/system-prompt.fixture.json` 两手面 + 受影响快照），`record:convergence` **双轨**重录。
6. 门禁：`vitest` / `build` / `biome ci` / `verify:convergence` 双轨 / `doc-check`。

## 5. 验收（可复算，不含主观项）

重启前写一条记忆 → 重启 → 重开同一卷 → **首个请求命中率应仍 ~99%（而非 0.6%）**。
判据 = `.lantai/logs/ui.log` 的 `llm response` 行（`hit` / `prompt` 两字段）。
