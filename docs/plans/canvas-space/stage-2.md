## 0. 一句话

把「单会话一张纸」改成「**一个工作区一张纸，多个会话流区共享同一视口**」。纸还是一整片，但上面能同时摊多个会话，各自流，互不打架，位置可放。

## 3. 核心概念改造

**流区（StreamRegion）= 一等空间概念**：`{ sessionId, anchorX, anchorY, width }`。anchor 就是“线性排比/用户放置”的位置，流从锚点向上长。

- **布局**：从「全局单栈一次算」改「每流区独立栈」——`layoutRegion(blocks, anchor)` 复用现有 `layoutFlow` 的相对逻辑，整体平移到该流区锚点。这是“单流区更新=常数”铁律的根基：一个会话吐字，只重算它自己的栈。
- **虚拟化**：每流区一个 flowGeom 数组，视口窗口跨流区查（流区数量少，成本 O(流区数 × log n)）。
- **宿主模型第一步**：流区位置属工作区级持久化；公共物（工作区级宿主）数据结构在此阶段预留，UI 落地在后续阶段。

## 3.5 定案（2026-08-25 痞老板审）

- **流区宽度 = 1440**（720×2，先试，落地看手感再调）
- **线性排比间距 = 720**（吸附网格粒度 = 宽度 + 间距）
- **流区移动 = 边缘拖动**（拖流区左/右缘移动整个流区，宽度不变；**鼠标悬停边缘即进入拖拽态（光标变 move），不做显式手柄条**——窗口边缘 resize 的手感，功能是移动；与块头手柄“拖块钉住”手势同族，不发明新形态）
- **不并存**：画布即主界面，不留单会话全屏老入口
- **首页适配（方案 A）**：SessionsHome 改“工作区总览”——只做工作区列表 + 进入动作，选完进画布；工作区内的会话管理交给画布旁的最小侧边栏（新建 + 列表）。完整侧边栏能力（状态点/行操作/折叠）留阶段 3

## 4. 子任务分解（拓扑序，每个子任务独立可测）

**4.1 数据层：流区位置模型 + 工作区级持久化**
- paper-store 扩展：`sessions[].anchor`（流区位置）、`activeRegionId`（活跃流区）
- 流区位置随工作区快照落盘/恢复（对齐 session-unify 的 workspace 语义）
- 线性排比落位：新建会话时 `anchorX = 上一个流区 + 间距(720)`
- 可测：store 单测——新建/移动/恢复流区位置

**4.0 出生最小路径（新增：画布能用的最低配置）**
- SessionsHome 适配为“工作区 → 画布”导航（最小程度：点工作区进该工作区画布、关卷回首页总览）
- 最小新建会话入口（按钮，落位画布线性排比）——完整侧边栏（状态点/行操作/折叠）留阶段 3
- 可测：实机——首页进工作区画布 → 新建会话 → 落位画布 → 再建一个并排

**4.2 布局层：单锚 → 多锚**
- `layoutFlow` 改为接受流区锚点，产出该流区块的世界坐标
- 布局只按流区重算（增量：哪个流区变只算哪个）
- 可测：布局单测——两流区各自坐标正确、互不牵连、移动锚点整体平移

**4.3 虚拟化层：跨流区可见窗口**
- `visibleFlowWindow` 扩展为跨流区：视口矩形 → 各流区可见块集合
- 可测：虚拟化单测——多流区下视口窗口只含可见块

**4.4 渲染层：多流区渲染 + 边缘拖动 + 吸附网格**
- PaperPanel 从“单会话渲染”改“视口内流区渲染”
- **流区边缘手柄 = 拖动手柄**（拖左/右缘窄条移动整个流区，宽度不变，吸附网格；对齐块头手柄手势同族）
- 块级 memo 隔离（延续第一阶段性能工作：一个流区更新，其他流区块纹丝不动）
- 可测：实机——两会话并行摊开，各自流，互不干扰

**4.5 空间内核 + ctx.space 打孔**
- space 内核模块：流区注册表、活跃流区、空间命令（定位/展开/落位/收起）
- `ctx.space` 通道（挂根 Context，对齐 services 通道的 register→Disposer 契约）
- 本阶段只打孔不消费：写一个 demo 插件验证能读到画布状态即可
- 可测：vitest——通道注册/读取/订阅

**4.6 性能常数落地**
- 布局隔离 + 增量测量 + 合并帧（延续第一阶段，落进多流区形态）
- 可测：性能基准场景走查（上百会话 + 多 Agent 同跑不卡）

**4.7 旧路径拆除（原则四）**
- 单流 `layoutFlow` 旧调用点改造后移除
- paper-store 里"单会话假设"清理
- 旧"手动切活跃会话"路径过渡到"活跃流区"

## 5. 技术方案要点（Agent 执行用，简略）

- **流区布局**：`layoutRegion(blocks, anchor)` = 现有 `layoutFlow` 相对坐标 + `translate(anchor)`。锚点 = 流区左下（流从锚点向上长，对齐现有 D-R1-3 流锚语义）。
- **虚拟化**：`visibleRegions(viewportRect)` 先筛视口相交的流区（矩形相交），再对每个流区跑二分窗口。流区数少，成本可控。
- **流区拖移**：拖顶部栏 → 更新 anchor（吸附网格）→ 该流区整体平移（布局重算仅此流区）。渲染层 transform 语义复用。
- **ctx.space**：`ctx.space.register(def)` 通道 + 读取面 `activeSpaceRegions()`，对齐 services.ts 的模块级"活动服务"间接层模式。空间命令 = 一个命令总线（定位到某流区 = 视口移动 + 高亮）。

## 6. 插件化约束（原则二/三）

- **空间内核（流区/锚点/布局/虚拟化）= 核心代码**，但它只做"纸怎么存在"，不做"纸上面长什么"。
- **ctx.space 是本阶段唯一的"核心新增 API"**，后续书脊、目次带（阶段 3/4）全部以插件消费它，不再动核心。
- 本阶段验收含「demo 插件经 ctx.space 读到画布状态」，证明孔真的能用。
