## 0. 一句话

**画布是工作区级的集体空间，承载的是卡片（对话/笔记/Agent 产物），不是会话本身**；侧边栏管全局监控与目录，SpineRack 管画布内的空间定位。会话收敛成画布上的一张「对话卡片」。

## 1. 已定概念（逐条记录拍板）

### 1.1 画布最小单元 = 卡片，不是会话

- 画布铺的是**内容卡片**：对话卡片、笔记卡片、Agent 产物卡片。
- 一个会话不是画布上的一整片，它**收敛成一张「对话卡片」**，与旁边的卡片并排，不打扰彼此。
- 心智支柱：解决"多个会话怎么合理存在于一个画布"——问题从"怎么放多个会话"变成"怎么组织卡片空间"。

### 1.2 同一画布 = 同一工作区（强约束）

- 画布的空间天然是**工作区级**的：一个画布视图同时铺开的多个会话，一定是同一工作区的。
- 推论：画布不能兼容不同工作区的内容，否则会乱。
- 两级结构：**全局目录管"会话在哪"（跨工作区），画布管"这个工作区的空间里铺什么"（工作区内）**。

### 1.3 两级互补：侧边栏（监控）vs SpineRack（定位）

**侧边栏 = 全局监控 + 目录**（DSH 范式）：
- 常驻、全量滚动、不截断
- 工作区分组 + Ungrouped 桶
- 会话行：状态点（pending/运行/子agent/完成）+ 标题 + 相对时间 + 行操作（改名/fork/归档）
- 管"整个档案馆有哪些会话、什么状态"

**SpineRack = 画布空间导航器**（兰台特色，2026-08-24 用户拍板）：
- 每个摊开的会话 = 书脊上一个**定位标签**（恒显）
- 点击标签 = **视窗复位**到该会话的最新消息（3D 视图"摄像机复位"语义）
- 标签带**状态点**：切走后运行中的会话仍亮着，随时知道它还在跑
- 改名/合卷等操作留在标签上（书脊是它们的老家）
- 管"画布上摊开的这几卷，快速定位到哪一卷的最新消息"

> 二者互补不冗余：侧边栏是"俯瞰档案馆"，SpineRack 是"入场画布"。监控与定位是两种能力，各管一摊。

### 1.4 SpineRack 的改造方向（替代退役）

- SpineRack **不退役**，从"卷列表"改造为"画布空间导航器"。
- 定位语义依赖会话/卡片在画布里的铺法，因此**SpineRack 改造挂在画布空间模型这一支**。
- 侧边栏展示层改造可独立推进，两条线在画布支汇合。

## 2. DSH 侧边栏参照（2026-08-24 实读）

来源：`d:/useful/deepseek-harness/packages/client/ui-sidebar/src/client/SidebarRoot.tsx`、`packages/client/ui-workspace/src/client/rows/Rows.tsx`

- 侧边栏壳：`sidebar.workspaces` 插槽承载工作区/会话浏览区；宽/窄两态（56px 窄轨）。
- 会话行（34px）：状态点 + 标题 + 相对时间 + 行操作菜单（rename/fork/archive）；blank 会话显示"新建会话"占位、无时间无操作。
- 状态优先级：pending 交互（approval/plan-review/question）> running > 子 agent > completed > idle。
- 组织：工作区文件夹行（展开/收起）+ 组内会话 + Ungrouped 桶；搜索 flat 列表。
- 行操作走 Menu（portal）；悬停 HoverCard 显示完整标题/时间/状态。

**对照兰台现状的差距**（SessionsHome）：两层截断（数据 50 条 + 渲染 slice(0,8)）、无状态点、无行操作、绝对日期、静态卡片形态。改造方向 = 去截断 + 状态点 + 行操作 + 相对时间 + 常驻滚动。
