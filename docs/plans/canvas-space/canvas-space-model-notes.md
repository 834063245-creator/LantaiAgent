## 0. 一句话

**画布是工作区级的集体空间**：第一层导航是工作区，一整个工作区就是一块画布。画布上铺的是**有界流区**（会话）和**公共物**（工作区级宿主）；侧边栏管当前工作区的会话管理（含新建），SpineRack 管画布内空间定位，创作坞（带设置的输入条）管配置与输入。

## 1. 已定概念（逐条记录拍板）

### 1.1 ~~画布最小单元 = 卡片~~（提案，未拍板）

> ❌ 2026-08-25 用户声明：**从未拍板「卡片为画布最小单元」**。此条是 session-unify 划边界时的临时约定，被记录者误升格为拍板，降级为提案。
> 提案原文（保留供讨论参考，不代表方向）：画布铺的是内容卡片（对话/笔记/Agent 产物），一个会话收敛成一张「对话卡片」；心智支柱是把问题从"怎么放多个会话"变成"怎么组织卡片空间"。
> 这个提案本身可能就走岔了：它预先把画布假设成"物件桌面"，而纸壳哲学的"一片连续的纸"是完全不同的另一条路。两者取向相反，须用户定夺。

### 1.2 同一画布 = 同一工作区（强约束）

- 画布的空间天然是**工作区级**的：一个画布视图同时铺开的多个会话，一定是同一工作区的。
- 推论：画布不能兼容不同工作区的内容，否则会乱。
- 两级结构：**全局目录管"会话在哪"（跨工作区），画布管"这个工作区的空间里铺什么"（工作区内）**。

### 1.3 两级互补：侧边栏（会话管理）vs SpineRack（空间导航）

> ⚠️ 2026-08-25 修正：**第一导航是工作区**，侧边栏身份从“全局监控 + 目录”收窄为「**当前工作区的会话管理**」——跨工作区总览在首页/工作区列表那一层（工作区=第一层导航）。侧边栏跟着工作区走，进了哪个工作区管哪个工作区的会话。DSH 能力全抄（状态点/相对时间/行操作/Ungrouped/搜索），作用域收窄。

**侧边栏 = 当前工作区的会话管理 + 出生仪式**（DSH 范式）：
- 常驻、全量滚动、不截断
- 工作区分组 + Ungrouped 桶
- 会话行：状态点（pending/运行/子agent/完成）+ 标题 + 相对时间 + 行操作（改名/删除；fork 后置、归档已砍——需求被「收起+侧边栏全量」覆盖，见 stage-3 §3.5）
- **新建会话按钮在此**（出生动作）：点一下，新会话诞生并自动落位到画布（线性排比/自动找位）
- 管“这个工作区有哪些会话、什么状态”

**SpineRack = 画布空间导航器**（兰台特色，2026-08-24 用户拍板）：
- 每个摊开的会话 = 书脊上一个**定位标签**（恒显）
- 左键=定位器（会话不在纸上则自动摊回当前视野再定位）；拖动=落位；hover 小卡=合卷（2026-08-25 用户反馈：书脊右键菜单取消，改名/删除归侧边栏）
- 标签带**状态点**：切走后运行中的会话仍亮着
- 管“画布上摊开的这几卷，快速定位到哪一卷的最新消息”

> 三者分工：侧边栏管会话死活（管理+出生），SpineRack 管空间定位，创作坞（带设置的输入条）管配置+输入+追加。监控与定位是两种能力，各管一摊。

### 1.4 SpineRack 的改造方向（替代退役）

- SpineRack **不退役**，从"卷列表"改造为"画布空间导航器"。
- 定位语义依赖会话/卡片在画布里的铺法，因此**SpineRack 改造挂在画布空间模型这一支**。
- 侧边栏展示层改造可独立推进，两条线在画布支汇合。

## 5. 画布支讨论实录（2026-08-25，逐条真拍板）

> 本节记录痞老板逐条确认过的拍板，与 §1 提案区分。前置纠正：§1.1「卡片为最小单元」非拍板已降级，见 §1.1 注。

### 方向定调

- 画布 = **一整片会生长的纸**（连续视口，平移缩放全局），不是物件桌面（Figma/Miro 那一路）。纸的哲学是连续，不是拼贴。
- 纸只有一层，即工作区级；会话是纸上流动的东西，**公共钉子属于纸本身**。不设「会话级/项目级」多层画布套娃。

### 拍板条目

1. **有界流区**：每个会话的流在纸上有边界，长到界就封边，不越界。无界流会乱套（用户原话）。
2. **统一宽度**：流区宽度统一，不做可调宽窄，省复杂度、秩序感优先。
3. **线性排比**：新会话默认落在上一个会话右侧（X 线性延伸），像开新标签页但共享同一片视野。
> ⚠️ 2026-08-26 Stage-5 用户拍板修正：自动落位改**最近空位（不分栏）**——以当前视口中心为参照、向左右逐列外扩找最近空列（`paper/space.ts` `nearestFreeRegion`），不再 X 线性无限延伸（会话多了会一字排开成傻长横带）；且**展开绑定视角聚焦**（落定后 requestFocus，兜底「一定找得到」）。收起 = 释放位置（重展开重新自动落位）。见 `stage-5.md`「后续精调」。
4. **操作界限原则**：系统能定的不让用户定。自由放置的交互与认知成本高，只保留最少放置动词：新建自动落位、拖顶部栏移动（吸附统一宽度栅格）、钉（落公共空间）。生长（Y 轴）系统自动。
> ⚠️ 2026-08-25 Stage-2 展开定案细化：移动手势落为**拖流区边缘**（拖左/右缘移动整个流区，宽度不变，吸附统一宽度栅格，无手柄条——见 `stage-2.md` §3.5/§8）；早先「拖顶部栏」表述作废，以边缘拖动为准。
5. **公共信息归纸不归会话**：plan/批注等公共物钉在流区间空处（古籍版式类比：会话流=界栏，公共钉=眉批/天头地脚）。
6. **宿主模型（核心机制）**：空间里只有一种基本单位叫**宿主**。所有东西要么是宿主，要么依附于宿主（依附物=批注/标记/分析，挂宿主身上，宿主生灭决定依附物生灭）。每个宿主只回答一个问题：**它跟会话同生共死（会话级宿主），还是独立于会话（工作区级宿主）**。单一决策点：把一个宿主从会话级升级为工作区级（钉/拖出），依附物自动搭车。公共物是独立的宿主，不靠任何会话供养，会话退场它仍在，天然正当（解决“孤儿钉子”隐忧）。paper 内核的块 + 稳定 id + 活引用即现成宿主。**公共物位置独立推论**：位置也是宿主自己的（吸附网格、可散落纸面），跟任何会话无关，会话退场它原地站着。
7. **会话退场 = 彻底退场**：归档/删除时流区从纸面完全退场，空间腾出；系统不自动重排，布局完全交用户自己摆弄（用户原话）。系统管秩序下限（统一宽度/吸附网格/新建默认落位），用户管布局自主——两层不矛盾。
8. **三层导航分工**：第一层=工作区（首页/工作区列表，一整个工作区=一块画布，创建/切换工作区在此）；第二层=工作区内（侧边栏=**当前工作区**的会话管理，含新建会话按钮=出生仪式；画布=空间）；第三层=画布内（SpineRack=空间导航，左键定位/拖动落位/右键菜单；创作坞=配置+输入）。「输入即诞生」否决，改「侧边栏出生，创作坞喂养」。
9. **创作坞**：带设置的输入条，常驻画布元素，状态跟活跃目标走（自动选中+高亮已定）；设置项贴输入条（模型/模式 plan|normal/参数/工具开关，展开收起），发送前顺手拨；设置页只管真正全局的东西（API Key/插件安装）。空白画布无活跃会话时处于无主待命态。
> ⚠️ 2026-09-10 修正：「自动选中」已退役——状态跟活跃目标走 = **显式激活 + 高亮**（详因见下方输入区归属拍板的 2026-09-10 修正）。
> **创作坞状态归属铁律（2026-08-25 拍板）**：创作坞是视图不是容器，不拥有任何会话状态，只“指向”当前活跃会话。每会话持有一个完整状态对象：用户可热切换的（模型/思考强度/权限——改了立即生效，下一条消息即用）+ 自动在涨的（token 计数/上下文占用/压缩状态——惰性计算 + 缓存，切换时直接读不重算）。切换会话 = 创作坞指针换向，不迁移不重算；草稿按会话隔离存储，切回还在。切换成本与状态多寡无关，永远是换引用级别。
10. **目次带（卷内导航，会话内 minimap）**：长流会话的定位控件，替代滚动条。骨架 = 轮次锚点（每个 user 输入一个刻度，位置映射相对高度）+ 点击跳转（视口飞到该轮）+ 位置指示（当前视口位置在带上的刻度）+ hover 首句预览；可选增强：plan/代码/报错等关键时刻不同标记。**位置语义：屏幕固定、内容跟随**——目次带是视口坐标（右缘窄条），归属当前活跃会话（自动选中机制，与高亮同主人），活跃会话切换则内容切换；概念上每会话一个实体，显示上只有活跃的出现。与创作坞同级（视口固定 + 跟随活跃会话的附件）；书脊左缘管卷外、目次带右缘管卷内。命名借用 minimap，兰台名（目次/脉络）待定。
> ⚠️ 2026-09-10 修正：括号内「自动选中机制」已退役——目次带归属活跃会话的语义不变，活跃会话转移 = 显式动作独占（详因见下方输入区归属拍板的 2026-09-10 修正）。
11. **画布布局持久化（2026-08-25 拍板，Q-B 在画布语义下不再适用）**：工作区画布为基本单位后，「展开」= 用户决定把会话摊在画布上 = **永远展开**（重启恢复）。需工作区级布局持久化：一份画布布局状态（摊开集合 + 流区位置），随工作区走，非每卷自带。与公共物（工作区级宿主）同一归属——将来布局 + 公共物合一为「工作区画布状态文件」。两级结构清晰化：会话消息跟卷走（全局位），画布布局跟工作区走。当前实现 region 随卷快照（卷级）为过渡形态，需升级为工作区级。
> **推论（2026-08-25 用户反问点破）：会话不跨工作区。**「跨工作区续开」是列表世界（session-unify 全局目录）的残留，画布模型下同画布同工作区是强约束，画布只摊当前工作区卷；想看别的工作区卷 = **切换工作区（换桌）**，不是搬卷。卷不跨桌 → 「位置跟卷走」与「位置跟桌走」实际无差别（卷永远只在归属桌摊）；真正的工作区级状态 = **摊开集合**（桌上摊了哪些卷），重启恢复画布 = 恢复摊开集合 + 各自位置。
> **特例待定：零目录卷（Ungrouped，workspace:null）**——无归属桌，在哪摊？（只能首页打开不进画布 / 摊开被画布接管 / 一直待首页 Ungrouped 桶）——2026-08-25 记录，回头单独拍。

12. **不做单一容器大重构（2026-08-26 拍板）**：经利弊全账评估，采纳「**概念统一**」、否决「**数据结构大重构**」。概念统一 = 所有东西都属于工作区画布，取消「两类宿主」二分，改用「画布物件」语言（流区随会话生灭 / 常驻物钉到拔为止）——零成本纯收益，落语言即可。大重构不做：收益大头是概念的（心智简化/生命周期统一表达/持久化单一——后者物理上做不到真单一，消息流必然外置），代价大头是实打实的（数据层根基重构/存量迁移/会话全局公民语义复杂化/测试面重写/短期零用户收益）。「工作区画布状态文件」（布局 + 公共物合一）仍按五阶段原计划落地，消息流保持外置。长期若画布形态稳定后仍想收敛数据层，作为专门重构阶段再评估，时机在稳定后，不叠在施工密集期。
13. **公共物定义 + 写写画画暂缓 + 零目录退役（2026-08-26 拍板）**：
- **公共物 = 不绑死会话的一切**：钉住块/纸条/布局位置/将来的批注，只要不跟会话绑死就属于公共物（工作区级，宿主模型完整落地定义）。
- **写写画画（手写笔迹）= 暂缓**：缺口挂起，不做。
- **零目录（定 a，2026-08-26）**：退役自动创建零目录会话动作（cold-start 占位 Agent 不再自动造无目录会话；无目录 = 首页选/建工作区，创建必须要有目录）。存量零目录卷**彻底退役**（绑目录或归档，概念最少）。用户判断：无项目随手开会话是真实场景，但不是单开功能的理由——用户完全可以在已创建工作区内开会话、用完删掉，无需「独立卷/虚拟工作区」概念。

> 2026-08-25 补充拍板：**输入区归属 = 自动选中 + 高亮**（阿阳技术方案，痞老板验体感）。核心：活跃会话是**有记忆的状态**，非每帧重算，只在明确条件满足时转移，这是“不乱跳”的全部。
> **转移三情形**：①显式动作（点击流区/输入条、书脊定位、拖动展开）立即切，零迟疑；②浏览态自动跟随，三道闸全过才切——视口停住（平移中不判）+ 中心点落在流区内 + 连续停留约 400ms（快扫不触发）；③缩放永不触发切换（缩放是读细节不改归属）；中心点在空白处保持当前。
> **输入锁存**：输入条获焦点/开始输入后自动跟随关闭，平移缩放均不打断，仅显式动作可切。高亮 = 活跃会话边界，指示“笔尖在哪”。体感类比：浏览是目光，输入是落笔；目光可飘，落笔钉住，除非亲手拿起放到别处。

> 2026-09-10 拍板修正（痞老板体感验收后）：**浏览态自动跟随（转移情形②）整体退役，活跃会话转移 = 显式动作独占。** 原拍板本就预留「验体感」环节——两轮实机（跟随坏死 P1-1 → 修补 → 呆看才切）之后，用户判「华而不实」。利弊账：收益面只有「平移看完直接打字省一次点击」，且创作坞书眉恒示归属卷名、显式路径（点流区背景/键盘跳卷/书脊/侧边栏/新建/摊开/恢复）全都在；成本面是**猜意图机器不收敛**——三道闸 + 400ms 停留 + adopt 防拉回 + 800ms 手动守卫 + 600ms 缩放守卫 + 输入锁存 + 命中区外扩 40px 全为它服役，且画布每加一个手势都要往「运动中不判」折叠再穿一根 ref（永久税）。「有记忆的状态」概念与高亮/创作坞/目次带跟随活跃会话的语义全部保留；输入锁存随宿主退役。若日后「看完就打字」的空档真硌手，确定性升级方向是「点输入框 = 显式动作，就近采纳视口中心流区」（零计时器），届时再拍。

> 2026-08-25 补充拍板：**性能基准场景（优化的靶子，用户拍板）**——同一工作区一张大纸，铺上百个会话（~100），同时 3~5 个 Agent 会话在跑，基于此场景优化。数字账：全工作区数据量 ~100 会话×~200 块≈2 万块（数据层，纯内存驻留，非压力）；常驻 DOM=视口可见 ~100-300 块（虚拟化保证，与总量无关）；压力集中在“同时动”。
> **性能总则**：内容多不贵（无限画布+虚拟化铁律：眼睛看不到的不渲染，渲染量只与视口可见块数相关，与总量无关；Figma 同级先例）；真贵的是多 Agent 实时流（多个流区同时吐新块 → 排版/测量/刷屏热点成倍）。
> **四项常数铁律（该场景下安全的前提）**：①单流区更新=常数（Agent 吐字只动自己流区末尾增量，块级 memo + 流区级布局隔离，其他 99 会话零接触）；②多流区更新合并成一帧（N 个 Agent 同时动=N 次增量更新/帧）；③浏览=常数（平移缩放只换 transform + 虚拟化窗口节流）；④测量=增量（只测新块，旧块高度全缓存，绝不因单 Agent 更新扫全工作区）。
> **三支柱**：①工作区级虚拟化（单会话视口升级为整张纸视口）；②增量与缓存（有更新的流区才重算，块高测量缓存，多流区更新合并一帧批量提交）；③分层渲染（纸面/内容/高亮输入条独立层各自刷新，小动画不拖累内容层）。
> **新增压力点（单会话没有）**：布局按流区隔离（每会话独立流栈，互不重算）、持久化/autosave 节流（上百会话不能每次全量存盘）、全工作区数据内存驻留。
> **验收标准**：该场景浏览 60fps、多 Agent 同跑 30fps。渲染层/逻辑层已解耦（translate/virtualize 纯函数），优化可全砸渲染层不动逻辑。

> 2026-08-25 补充拍板：**书脊标签手势三分**（一根手指三个动作各管一摊）：左键点=定位器（会话不在纸上则自动摊回当前视野再定位，系统找位）；拖动=落位（从书脊抽出，拖到“竖向不打架”的区域即在该处展开，用户指定位）；hover 小卡=合卷（2026-08-25 用户反馈收敛：书脊右键菜单取消，改名/删除归侧边栏）。零新增交互成本（拖动是鼠标天生能力，非新花样）；自动找位与用户指定位两档齐备，呼应“系统管秩序下限、用户管布局自主”。书脊隐喻用满：抽书 → 放桌 → 摊开。

## 7. 施工顺序（2026-08-25 拍板，拓扑序非优先级）

> 原则一：每一步交付的都是**能跑、能验、能感受到变化的完整切片**，不出现「全做完才能测」的断层（教训：零件堆一地，装完才发现交互对不上=全白堆）。
> 原则二（插件化分层，2026-08-25 拍板）：**空间内核=平台开放 API，上层形态=第一方插件**。内核只长「空间 API」这一块，侧边栏/书脊/创作坞/目次带/写写画画全部以插件贡献行落位，核心纹丝不动。插件化的账已兑现（十二族工具/prompt 13 段/PANEL_DEFS 清空/paper 面板皆贡献形态）；衡量标准=把改动边界推到多小，不是全不写源码（平台本就该是源码，浏览器=引擎源码+网站插件）。
> 原则三（施工验收标准）：第二阶段立空间 API 后，第三到第五阶段每个功能形态验收都含「**以插件贡献行落位，不改核心（空间 API 本身除外）**」，实时验证插件化兑现，不等到做完才恐慌。
> 原则四（随做随清，2026-08-25 拍板）：清理是每阶段验收的一部分，**随做随清**，不是阶段后独立步骤（否则变成“先留着以后清”→永远清不掉→双轨残留=历史包袱成因）。机制三件套：①每阶段验收清单加「**旧路径拆除**」——本阶段替换/退役的旧行为/旧参数/旧存储路径阶段内拆干净，测试同步更新，不留双轨；②阶段末扫「**新引入的临时债**」——本阶段为连通性留的 hack/兼容分支登记限期清，不带入下一阶段；③门禁照旧（测试全绿+build+biome）+ 无旧路径残留核查。不清旧=重演“交互乱七八糟没法实机测试”教训（旧逻辑还活着跟新的打架）；成本随阶段指数涨。
> 原则五（阶段展开流程，2026-08-25 拍板）：**每阶段开工前 = Agent 起草阶段展开 + 用户审**。总设计笔记（本文件）全阶段共享不重写，阶段展开只是“翻译+分解”（子任务清单/技术方案/验收清单/动哪些文件与孔），非重新设计，故快不重。分量随阶段复杂度走：二阶段架构级重文档、三四阶段中清单、五阶段轻量。分工：Agent 管执行与拆解，用户审蓝图+验收结果，每步无空转。第一阶段特例：目标明确（两热点+验收四项），直接干不等展开。
