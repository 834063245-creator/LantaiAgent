# Stage-3 会话的出生与管理（画布支第三阶段展开）

> 立项：2026-08-25 · 状态：**已落地（2026-08-25，门禁全绿）** · 类型：阶段展开（Agent 起草 → 施工完成）

> 施工纪律：原则一（每步可测切片）· 原则二/三（空间内核=平台+API，上层形态=插件行落位不改核心）· 原则四（随做随清）

## 0. 一句话

把 Stage-2 的「书脊 + 最小卷目目录」二合一，拆成两套完整能力：**侧边栏 = 当前工作区会话管理（DSH 范式，可折叠）**，**书脊 = 画布空间导航器（左键定位 / 拖动落位 / hover 合卷）**。会话生命周期在画布上闭环：新建 → 落位 → 收起 → 拖出 → 菜单归档。

## 1. 目标与验收（用户视角）

**验收一句话**：新建 → 落位 → 收起 → 拖出 → 菜单归档，整条会话生命周期在画布上闭环。

- [x] 侧边栏 = 当前工作区会话管理：状态点（pending/运行/子 agent/完成）+ 相对时间 + 行操作（改名/fork/归档）+ 常驻滚动 + **可折叠** + 新建按钮（出生仪式）
- [x] 书脊 = 画布空间导航器：左键=定位器（摄像机复位，轻动画）、拖动=落位（抽书放桌）、hover 小卡=合卷（用户反馈：书脊右键菜单取消，改名/删除归侧边栏）
- [x] 会话生命周期闭环：侧边栏新建落位 → 画布摊开 → 书脊收起退场 → 书脊拖出重新摊开 → 菜单删除
- [x] 侧边栏与书脊布局分离，各管一摊（结构决策见 §3.5）
- [x] 插件化落位：侧边栏/书脊以贡献行消费 ctx.space，不改核心（原则三）
- [x] 旧路径拆除干净（旧 SpineRack 单列、旧「单击换卷」语义），门禁全绿

## 3. 现状到目标的差距（二合一 → 两套）

**SpineRack 现状已有什么**：书脊标签（卷名 + 运行点 + hover 卡 + 合卷）、另起一卷、卷目目录（最小列表：磁盘卷清单 + 摊开）。
**缺什么**：三手势（现在是单击换卷，不是定位器；无拖动落位；无右键菜单）；侧边栏 DSH 能力（状态点全谱、相对时间、行操作 fork/归档、常驻滚动、可折叠）。

## 3.5 结构决策（已定 2026-08-25 痞老板审）

- **布局方案 A**：书脊恒显最左缘（窄条，空间导航，三手势）+ 侧边栏在其右（可折叠的会话管理面板，收起来只剩书脊）。监控与定位各管一摊。
- **书脊右键菜单取消（2026-08-25 用户反馈）**：书脊只管空间定位，功能别太多——改名/删除归侧边栏（会话管理那一摊）；书脊 hover 小卡恢复「合卷」（收起，数据保留 + 自动存）。fork/只读后置不变。
- **归档功能砍掉（架构红利）**：归档 = 列表世界的软删除/列表整理（会话容器是列表，越积越乱），画布模型里该需求已被「收起=流区退场（数据保留、侧边栏全量可见）+ 侧边栏管理」天然覆盖——我们根本没有列表爆炸这个病，不需要补救机制。
- **fork 后置（需求真实但与空间无关）**：对话线性 vs 思考分叉——从第 N 轮换方向保留上下文。画布上「钉出某块当新起点」可替代一部分；低频，后置可拾。
- **只读后置（需求很弱）**：防误改 + 安全查看，多为协作场景；单用户 + 收起即退场，误触风险低。
- **定位器视口行为 = 轻动画过渡**（非瞬移）。

## 4. 子任务分解（拓扑序，每个子任务独立可测）

**4.1 侧边栏 DSH 能力**
- 当前工作区会话全量列表（含未摊开卷，去截断、常驻滚动）
- 状态点全谱：pending 交互 > 运行 > 子 agent > 完成 > idle（对齐 DSH 优先级）
- 相对时间、行操作（改名/fork/归档）、新建按钮（出生仪式，复用另起一卷语义）
- 可折叠（折叠后只剩书脊）
- 数据源扩展：当前工作区会话状态需要「未摊开卷也有状态」，核对 listSavedSessions 语义
- 可测：侧边栏组件单测 + 实机（开多个会话看状态点/相对时间/行操作）

**4.2 书脊空间导航（定位 / 拖落 / hover 合卷）**
- **左键 = 定位器**：复用 ctx.space.focus + 视口复位（摄像机飞到该流区最新消息；不在纸上先 expand 再飞）。替换旧的「单击换卷」
- **拖动 = 落位**：从书脊拖出标签 → 拖到画布「竖向不打架」区域 → 松手在该处展开（ctx.space.expand + place 组合）。拖拽过程幽灵预览
- **hover 小卡 = 合卷**：改名/删除归侧边栏（用户反馈：右键菜单取消）；书脊只留「合卷（自动存）」
- 可测：书脊组件单测（手势分发）+ 实机（定位/拖落/hover 合卷各走一遍）

**4.3 会话生命周期闭环**
- 侧边栏新建 → 落位画布（线性排比，复用 Stage-2 落位）
- 书脊收起退场（collapse，流区彻底退场不重排）
- 书脊拖出重新摊开（expand + place）
- 菜单**删除**（彻底移除，公共物不受牵连；无归档态——收起即软删除，需求已覆盖）
- 可测：实机——完整生命周期走一遍（新建→落位→收起→拖出→删除）

**4.4 插件化落位（原则三）**
- 侧边栏走面板贡献（ctx.panels）或空间导航覆盖层通道
- 书脊消费 ctx.space（getState/subscribe/四命令），不新增核心 API
- 归档/删除动作走现有 core 会话命令（closeSession/loadSessionFromDisk 同族）或新增薄壳
- 可测：vitest——侧边栏/书脊以贡献行注册、消费 ctx.space 对拍

**4.5 旧路径拆除（原则四）**
- 旧 SpineRack 二合一结构拆解后的残留清理
- 旧「单击换卷」语义替换为「左键定位器」后的死代码拆除
- hover 小卡与右键菜单职责重叠的收敛（用户反馈：书脊右键菜单取消，hover 小卡只留合卷）
- 可测：门禁全绿 + 无旧路径残留核查

## 5. 技术方案要点（Agent 执行用，简略）

- **定位器视口行为**：focus 后视口动画/瞬移到目标流区最新块位置（复用 viewForAnchor 语义，锚到流区而不是全局锚）；不在纸上 = 先 expand 摊回（线性落位）再飞。
- **拖动落位**：书脊标签按住 → 进入画布坐标 → 幽灵预览流区形状 → 找「竖向不打架」的空位判据（复用 Stage-2 吸附网格/落位判据）→ 松手 place。
- **状态点数据源**：对齐 agentSessionState（exec.isRunning）+ pending 交互信号（approval/ask）的来源核对；未摊开卷状态可能需扩展 listSavedSessions 返回状态。
- **侧边栏面板**：若走 ctx.panels，side:'left' + unmountOnClose；可折叠形态由面板壳层支持（核对现有 DockPanel 折叠能力）。

## 6. 插件化约束（原则二/三）

- 侧边栏/书脊 = 上层形态 = **插件/贡献行**，不改核心（空间 API 在 Stage-2 已打孔，本阶段只消费）
- 唯一可能的新核心面：会话状态（pending 优先级/归档态）若现有 store 不支持，需要小步扩 store 语义（属核心数据层，非 UI 形态）——列为「若需要则小扩」
- 验收含「侧边栏/书脊以贡献行注册」证据
