# 出处引导（pin-provenance）——钉住块的「从哪来」

> 立项：2026-09-18（用户报：「这些块没有一个视觉引导——拖下来之后完全不知道这东西从哪来；
> 会话流中的占位不在视口里，根本起不到任何引导作用」）。
> 性质：**视觉 + 交互新增**（不动手势、不动数据约定；`WorkspacePin.source.label` 是可选字段，旧档照读）。
> 状态：**代码已落地**（门禁见 §5）；**余真机体感验收**（§6，owner：用户）。

## 0. 病灶（机理，不只是现象）

钉块与源块之间只剩流内占位（`.pp-ghost`）一个记号，而占位是**视口内**的线索：

- 流自锚点**向上**生长——`canvas-math.layoutFlow` 自底向上累积（最新块贴锚点），`regionTop = min(flowGeom.y)`
  单向增负 ⇒ **洞随新墨越漂越远，钉留在原地**；
- 渲染按视口窗口化（`virtualize.visibleFlowWindow`）⇒ 洞不在视口里时**连 DOM 都不存在**。

于是「从哪来」这个问题，在长卷 / 挪过视口 / 重启恢复之后**没有任何可见答案**（用户原话的
「占位不在视口里就起不到引导作用」正是第二条机理）。

## 1. 定案（两条腿 + 一个手势）

| 件 | 形态 | 为什么这么定 |
|---|---|---|
| **出处行** `.pp-prov` | 页边注（文类签）第三行「摘自 卷名 · 状态字」，**常显** | 出处是页边注的本职（这条注疏对着哪段正文）；常显 ⇒ 不依赖任何视口内目标 |
| **引线** `.pp-tether` | hover 钉块 → 世界坐标发丝直线（钉缘 → 洞缘）；**洞离屏时线照样出屏** | 空间那条腿：方向即来路。一屏一线（钉多起来全画就是乱麻）⇒ hover 期存在 |
| **溯源** | 点出处行 → 飞到源洞（`flyToPoint` 落洞中线）+ 洞点名一拍（1.6s 自散） | 把「知道」变成「到达」。反向（流内 → 钉在哪）本批不做，见 §3 |

**出处状态字**：活钉无字（常态不加字）/ `不在卷内`（卷摊开而源块没了：撤回、压缩）/ `未摊开` / `已删`
——`已删` **不可点**（不发起必然落空的定位/摊开，2026-09-10 收口纪律）。

**卷名来源**（单一权威链）：活卷读活卷名（`r.label`，权威）→ 孤儿钉读**建钉时刻冻结**的
`pin.source.label`（与 `snapshot` 同一条「公共物不连坐」语义）→ 都没有则档号兜底
（`volumeDisplayName`，禁在调用点散写 `label || 案卷 N`）。超长卷名在**纯层**截断（10 字 + …，
状态字不受截断影响）。

**引线选边**（`tetherLine`）：净空优先——洞全在钉左 → 钉左缘接洞右缘；全在右 → 钉右缘接洞左缘；
**横向相叠** → 两侧都取左缘（相叠时洞的右半被钉盖住，指向它等于没指，故线往左出去不横穿钉身）。

## 3. 刻意不做（留后）

- **全展引线**（一键把全部钉的引线一起画出来 = 接线图）：钉多时是面条，先看 hover 档够不够用。
- **反向引导**（流内洞位标「已钉在画布」+ 一点飞到钉）：对偶方向，用户没提，留作后手。
- **引线跟随拖拽**已顺手做了（拖动中读跟手位，线随块走 = 拖回洞位的手感依据）。

## 4. 连带修复：飞行动画不混钟（本批查出，非本功能）

`flyToPoint` / `glideViewTo` 原以 `t0 = performance.now()` 起算、`now` 取 rAF 回调时间戳
（`t = Math.min(1, (now - t0) / DURATION)`）。两把钟不同源时 `now < t0` ⇒ `t` 为负 ⇒ `ease`
为负且越走越负，而 `t < 1` 恒真 ⇒ **rAF 循环永不终止、视口一带一路飞出内容之外**
（jsdom 实测：now 4968 vs t0 6268 ⇒ t = −5.4、单帧 panY 位移 −17 万 px，四帧内 panY 到 −167,062）。

真机 Chromium 两钟同源（都是 time origin 起算的 `DOMHighResTimeStamp`）故不触发，但「循环靠
两把钟恰好对齐才终止」不该是契约。现改为 `progressOf` 单一实现：① 起点取**首帧 rAF 时间戳**
（同一把钟，环境无关）；② 进度夹 [0, 1]（单调不减 ⇒ 到 1 即收尾，循环必然终止）。
**真机行为零变化**（同源时两者等价）；jsdom 行为面因此可考（⑪ 段溯源用例即回归考官）。

## 6. 真机验收（owner：用户）

1. 拖一块钉住 → 页边注第三行出现「摘自 卷名」（**不等 hover**，卷名是真名不是档号）。
2. hover 钉块 → 一丝朱砂线从钉子拉到流内洞位；**把视口挪到洞不在屏内**再 hover——线应出屏、方向指得对。
3. 点出处行 → 视口飞到洞里（洞落屏中心）+ 洞闪一下；洞上原来的「已移出 · 点击恢复」手势不变。
4. 把源卷收起（或重启后只留钉）→ 出处行写「未摊开」，点它 = 摊开该卷并定位。
5. 删掉源卷 → 出处行写「已删」，点了没反应（title 说明「源卷已删除——无法回溯」）。
6. 重启 → 上述不变（卷名从 `canvas-pins.json` 回读，不依赖源卷在场）。
