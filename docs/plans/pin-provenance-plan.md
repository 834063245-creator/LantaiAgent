# 出处引导（pin-provenance）——钉住块的「从哪来」

> 立项：2026-09-18（用户报：「这些块没有一个视觉引导——拖下来之后完全不知道这东西从哪来；
> 会话流中的占位不在视口里，根本起不到任何引导作用」）。
> 性质：**视觉 + 交互新增**（不动手势、不动数据约定；`WorkspacePin.source.label` 是可选字段，旧档照读）。
> 状态：**代码已落地**（门禁见 §5）；**余真机体感验收**（§6，owner：用户）。

## 0. 病灶（机理，不只是现象）

钉块与源块之间只剩流内占位（`.pp-ghost`）一个记号，而占位是**视口内**的线索：

- 流自锚点**向上**生长——`canvas-math.layoutFlow` 自底向上累积（最新块贴锚点），`regionTop = min(flowGeom.y)`
  单向增负 ⇒ **洞随新墨越漂越远，钉留在原地**；
- 渲染按视口窗口化（`virtualize.visibleFlowWindow`）⇒ 洞不在视口里时**连 DOM 都不存在**。

于是「从哪来」这个问题，在长卷 / 挪过视口 / 重启恢复之后**没有任何可见答案**（用户原话的
「占位不在视口里就起不到引导作用」正是第二条机理）。

## 1. 定案（两条腿 + 一个手势）

| 件 | 形态 | 为什么这么定 |
|---|---|---|
| **出处行** `.pp-prov` | 页边注（文类签）第三行「摘自 卷名 · 状态字」，**常显** | 出处是页边注的本职（这条注疏对着哪段正文）；常显 ⇒ 不依赖任何视口内目标 |
| **引线** `.pp-tether` | hover 钉块 → 一丝**手绘朱笔**（划词朱线同族）从钉缘引到洞缘；**洞离屏时线照样出屏** | 空间那条腿：方向即来路。一屏一线（钉多起来全画就是乱麻）⇒ hover 期存在。见 §1.1 |
| **溯源** | 点出处行 → 飞到源洞（`flyToPoint` 落洞中线）+ 洞点名一拍（1.6s 自散） | 把「知道」变成「到达」。反向（流内 → 钉在哪）本批不做，见 §3 |

### 1.1 引线重做（2026-09-18 同批二刀，用户判「一根直线直连…有点劣质」）

一刀那版是**世界坐标的一根等宽直线**，两端贴死钉缘与洞缘。用户判劣质——判断成立，且病根不在
「线」而在**语言**：等宽 + 贴死 + 一笔到底的直线是**连线图**语汇，不是纸上的东西。

**治法 = 判例内转录**：本仓早有一支更高级的笔——**划词朱线**（`paper/sel-ink.ts` + `.pp-sel-ink`，
2026-09-02 立、用户拍板过）。引线整支改抄它：逐点正弦微伏 + 定种子相位（**同钉恒同线**，
重渲染/平移不闪）+ `smoothPath` 手绘平滑 + **恒定墨宽**（该判例的明文字律：**手感来自微伏
不来自粗细变化**）。四点按引线几何改写，每处记理由：

| 改写 | 理由 |
|---|---|
| 层改**屏幕坐标**（同 `.pp-sel-ink`） | 墨宽不随缩放变——世界 1px 在 zoom .3 下 = .3px，等于没画（引线是导航信号，缩远了更要看得见） |
| 微伏走**弦的法向** | 划词是横线（竖向微伏即可），引线可朝任意方向；纯竖向微伏在纵线上等于没有 |
| 叠一层**垂**（重力，只吃横向跨度） | 纯纵向的丝不垂（两端同轴没有可垂的余量）；横向跨度大才下垂——真丝挂在两点间的样子 |
| ~~起笔**留白 6px**~~ + 收笔**朱点** | ~~线飘出来，不插在盒子上（插头感正是劣质来源之一）~~ **2026-09-22 锚点批退役**——留白正是「没有固定锚点」的直接成因（用户判「感觉奇怪」）。现在两端都接在块缘那枚常显锚点上：**线是引，点是落，两头都是落** |

**弃（记录以防回漂）**：
- **等宽填充笔锋**（起笔粗/收笔尖的实心笔道）：与判例的明文字律直接冲突——「手感来自微伏
  不来自粗细变化」；且实心填充做不了描线动效，收益不抵背离。
- **双笔 echo**（划词的淡墨第二笔）：那是**短线**语汇（一行字下），长引线上会读成双线/毛边。
- **描线动效**（dashoffset 把线拉过去）：判例的克制是对的——hover 瞬时件加动画，钉多时
  每次划过都要等一次落笔；改用 `--snap` 档的不透明度渐显（`pp-tether-in`）。

**出处状态字**：活钉无字（常态不加字）/ `不在卷内`（卷摊开而源块没了：撤回、压缩）/ `未摊开` / `已删`
——`已删` **不可点**（不发起必然落空的定位/摊开，2026-09-10 收口纪律）。

**卷名来源**（单一权威链）：活卷读活卷名（`r.label`，权威）→ 孤儿钉读**建钉时刻冻结**的
`pin.source.label`（与 `snapshot` 同一条「公共物不连坐」语义）→ 都没有则档号兜底
（`volumeDisplayName`，禁在调用点散写 `label || 案卷 N`）。超长卷名在**纯层**截断（10 字 + …，
状态字不受截断影响）。

**引线选边**（`tetherAnchors`，世界坐标）：**面对面**——按两者的横向中线判「洞偏哪边」，
两端各取**朝向对方**的那条缘（洞中线在钉中线左 → 钉左缘接洞右缘；否则钉右缘接洞左缘）。
一条判据覆盖全在左 / 全在右 / 相叠三种相对位置。
**两端都落在锚点上**（高度一律块顶下 `TETHER_ANCHOR_DY` = 12px，见 §1.3）：引线**不留白**——
从锚点圆心出发、到锚点圆心收笔。
（2026-09-22 三刀改选边：旧规则「净空优先 + 相叠时两侧都取左缘」把落点送到背离钉的远缘，
线为够到它整条横穿该块正文——台架实测中距档 4 段正文 83 个采样点压在字上。见 §1.2。）

### 1.3 引线锚点（2026-09-22 锚点批）：每块两缘各一枚固定圆点

**病灶**（用户判）：「没有一个固定的锚点来连接引线，感觉奇怪」。机理是**两头都没有实体**：
起点被 `TETHER_GAP = 6` 推到块缘外的虚空里；而**钉块的 hairline 是 `display: none`**（便条批
「页边注随页边一起退役」）、流块的 hairline 又是 1px `--ink-4`——地标要么不在、要么看不见。

**治法**（用户提案）：**每个块左右缘各一枚固定圆点**作为锚点，引线两端都接在它上面。

| 决定 | 值 / 做法 | 为什么 |
|---|---|---|
| 位置 | `(块.x, 块.y + 12)` 与 `(块.x+w, 块.y + 12)` | **同一个相对位置**是这套锚点的全部意义；12px = 文类签 hairline 那一档（流块上正落在页边注连线末端，钉块上落在报头行里） |
| 形制 | **圆点**（4px） | 与「钉住」身份的**方墨点**分属两种语言——方 = 状态，圆 = 连接点（D2 方点语言） |
| 墨阶 · 显形 | **不常显**：`--ink-4`，**进入块才显形**（`.pp-block:hover .pp-anchor`，走 `--snap`） | 2026-09-22 用户判「专门加的锚点圆点没必要常显」——静态点是**零信息噪声**（引线本来就在两端各落一枚朱点）。同 `.pp-kind:hover` 那族「手柄可发现性」：hover 即示意「这里可以接」。显形时**不转朱砂** ⇒ 一屏至多一处红不破 |
| 引线两端 | 起笔 `pp-tether-origin` + 收笔 `pp-tether-bead`，各 r2.2 | 「线是引，点是落」——现在两头都是落 |
| 连带 | `.pp-kind::after` 宽 14 → 18px | 页边注 hairline 接上左缘那枚锚点，地标与锚点连成一条链 |

**层序定案**（同批，用户拍板）：**维持块之上**（`.pp-tether-layer` `z-index: 4`）——§2 原案
「块(z2) 之下——引线不穿字」由此**退役**。理由两条：① `.pp-world` 带 transform 即层叠上下文、
引线层是它的兄弟，「块之下」那一档拿不到（要拆世界层）；② 锚点批把「线接在实体上」做实之后，
穿字的代价由锚点与选边共同收窄。**ComfyUI 的「连线在节点之下」不再作为取齐目标。**

### 1.2 引线三刀（2026-09-22）：笔道换**切向贝塞尔**

**触发**：用户拿 ComfyUI 的画布连线为参照，判「观感质感好多了」。

**诊断先行**（`prototype/tether-pen-ab.NOTES.md`，实测不是印象）：二刀那支笔的问题在**几何**，
不在描边——墨宽实测 1.42px、峰值覆盖 1.00（与字面量逐位吻合），细/淡/发虚/锯齿四条嫌疑全排除；
而微伏振幅是**绝对量** 1.2px、频率 ≈1 个周期（这套参数是给划词朱线那种几十到几百 px 的短线定的），
搬到 600–1400px 的引线上，最大法向偏离只剩 2.68% → 0.47%——**实看就是一根尺子画的直线**，
2026-09-18 判死的那版在视觉上原样回来了。

**治法 = 转录 ComfyUI 的曲线定律**（`litegraphLinkAdapter.ts:241-294` 的 SPLINE 分支：控制点 =
端点 + 锚面法向 × 弦长 × 0.25），但**上限必须由我们给**：那条公式与弦长成正比且没有上限，
ComfyUI 两端永远同屏所以不炸，引线的洞可以在一屏之外（台架实测 1397px 弦 → 349px 臂长 →
240px 法向鼓包）。两道夹各记理由：

| 常量 | 值 | 为什么 |
|---|---|---|
| `TETHER_SPLINE_K` | 0.25 | 判例原值（弦长 × 0.25）——中距档因此与 ComfyUI 逐位一致 |
| `TETHER_SPLINE_MAX` | 160px | 臂长**绝对**上限：鼓包随弦长线性增长，洞越远越炸，而引线的弦长无界 |
| `TETHER_SPLINE_ROOM` | 0.6 | 臂长 ≤ 横向净空 × 0.6：纯纵向的丝没有可鼓的余量（同「垂只吃横向跨度」），dx→0 时退化成直线 |

**微伏与垂都留着**（纸面语义 + 「同钉恒同线」有防闪的功能价值），各改一处：垂的包络
`4t(1-t)` → `16t²(1-t)²`（**两端斜率归零**，不再破贝塞尔的水平切线）；微伏频率 ≈1 → ≈1.4–2 个周期
（低频大振幅读作「这根直线没画准」，高频小振幅才读作手抖）。

**同批连带改选边**（见上「引线选边」）：横穿的代价在三刀下不再是「压在字上」而是「整段被块盖住」，
更不允许横穿。

**证据**：`prototype/tether-pen-ab.html` 一·B 幕（辛 = 二刀 / 壬 = 三刀，同墨同场景），
起笔/收笔 6× 特写；`tether-pen-ab.辛一刀.png` / `.壬二刀.png`。
（台架同时修了一处**截图 bug**：`Page.captureScreenshot` 未开 `captureBeyondViewport`，
页面腰以下的舞台被裁错位——上一版据此误判「庚案曲线甩出画布」，实为台架自己没截到。
**裁错比裁不到更坏：它长得像结论。**）

## 3. 刻意不做（留后）

- **全展引线**（一键把全部钉的引线一起画出来 = 接线图）：钉多时是面条，先看 hover 档够不够用。
- **反向引导**（流内洞位标「已钉在画布」+ 一点飞到钉）：对偶方向，用户没提，留作后手。
- **引线跟随拖拽**已顺手做了（拖动中读跟手位，线随块走 = 拖回洞位的手感依据）。

## 4. 连带修复：飞行动画不混钟（本批查出，非本功能）

`flyToPoint` / `glideViewTo` 原以 `t0 = performance.now()` 起算、`now` 取 rAF 回调时间戳
（`t = Math.min(1, (now - t0) / DURATION)`）。两把钟不同源时 `now < t0` ⇒ `t` 为负 ⇒ `ease`
为负且越走越负，而 `t < 1` 恒真 ⇒ **rAF 循环永不终止、视口一带一路飞出内容之外**
（jsdom 实测：now 4968 vs t0 6268 ⇒ t = −5.4、单帧 panY 位移 −17 万 px，四帧内 panY 到 −167,062）。

真机 Chromium 两钟同源（都是 time origin 起算的 `DOMHighResTimeStamp`）故不触发，但「循环靠
两把钟恰好对齐才终止」不该是契约。现改为 `progressOf` 单一实现：① 起点取**首帧 rAF 时间戳**
（同一把钟，环境无关）；② 进度夹 [0, 1]（单调不减 ⇒ 到 1 即收尾，循环必然终止）。
**真机行为零变化**（同源时两者等价）；jsdom 行为面因此可考（⑪ 段溯源用例即回归考官）。

## 6. 真机验收（owner：用户）

1. 拖一块钉住 → 页边注第三行出现「摘自 卷名」（**不等 hover**，卷名是真名不是档号）。
2. hover 钉块 → 一丝朱砂线从钉子拉到流内洞位；**把视口挪到洞不在屏内**再 hover——线应出屏、方向指得对。
3. 点出处行 → 视口飞到洞里（洞落屏中心）+ 洞闪一下；洞上原来的「已移出 · 点击恢复」手势不变。
4. 把源卷收起（或重启后只留钉）→ 出处行写「未摊开」，点它 = 摊开该卷并定位。
5. 删掉源卷 → 出处行写「已删」，点了没反应（title 说明「源卷已删除——无法回溯」）。
6. 重启 → 上述不变（卷名从 `canvas-pins.json` 回读，不依赖源卷在场）。
