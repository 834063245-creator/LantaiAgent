## 本工程的性质（写给所有 agent——先校准预期，再谈管线）

**前端不是「一切定好就能做好」的转录流水线。** 定稿的契约（V2）只消灭「随机重掷」这一类失败；定稿之后仍有大量工作，形态是**高频率的沟通-修改-测试循环**：用户在真实使用中产生不满 → 描述不清的模糊反馈 → agent 猜测意图出候选 → 用户再判。这个循环是前端工程的**本体**，不是开销——观测台的现状就是非常多轮这样的循环磨出来的。本计划对它的态度：不消灭循环（消灭不了），而是给循环上纪律（V4 防发散协议：一环一维、对照反馈、账本、止损），让每轮循环都产生**留存的知识**（品味账本），而不是蒸发。

用户角色因此不是「短会话点缀」而是**共同创作者**——本工程的主要生产资料之一就是用户的判断力。给 agent 的排程含义：paper-shell 的推进节奏由用户对话带宽决定，agent 不催促、不擅自跳过人判环节、不用「契约已定」为由把循环压扁。

## 方法论：把「发明」压缩到最小，其余交给循环

| 任务类型 | Agent 能力 | 在管线中的合法位置 |
|---|---|---|
| 发明视觉设计（从构想产出新视觉） | ✗ 弱 | 只发生在 V1 一次性原型里；**人是唯一审美仲裁**（看 + 选） |
| 转录视觉（把已批准的视觉翻成代码/token） | ✓ 强 | V2 契约编码 + V3/V4 生产代码——**只许转录，不许现场发明** |
| 骨架工程（数据模型/布局数学/虚拟化/协议） | ✓ 强 | V3a 壳无关内核（纯逻辑，零视觉判断） |
| **共同创作循环（模糊反馈→候选→人判）** | **人机各半** | **V4 全程 + V5 之后的产品常态**——这是本工程的主体工作量 |

证据：`prototype/` 目录就是这条环路的非正式跑通——`paper-prototype-light.html` 已含完整 token 系统（desk/paper/folio/ink/brass 全套 + Fraunces/Noto Serif 字体对 + 动效曲线），`ink-brass-scene-v2.html` 是一个自洽的「墨与黄铜·观测日志」静物方向。视觉方向不缺，缺的是收敛决策、正式契约和骨架工程。

## 管线

### V0 — 愿景外化访谈（每轮 ≤4 问，小时级）

- **R1（即开）**：① 脑内缺口补全（开放题：文档没接住的部分）② 走查弹（tracer bullet）定义 ③ 块生产者 staging ④ 视觉收敛启动
- **R2**：交互细节——钉住/引用最小交互、两层转化通道、横向维度角色
- **R3**：迁移与退役——共居期长度、观测台退役判据
- 产出：本 README 相应节填满 + §6 清单逐项消账

### V1 — 原型收敛轮（每轮小时级，一次性 HTML）

每轮回答 §6 的具体视觉问题：**出 2-3 个变体 → 人看 → 选/混**。变体从既有原型派生，不重起灶。已可开的第一轮：白纸 vs 深色（两侧打样都在，可能只差一次并排看）。

纪律：原型是消耗品——原型代码**不许**进生产（进生产是 V2 转录的事）；每轮只回答清单上的问题，不顺手探索。

### V2 — 视觉语言编码（1-2 天，纯转录）

赢者原型 → `paper-tokens.css`（token 块在原型里已存在，照抄成正式文件）+ 组件清单（块渲染器类型 / 材质 / 投影 / 动效曲线）+ 金样截图若干张。

**这是视觉契约**：此后一切生产代码的视觉只从这里取。评审试金石：「这段视觉是契约里的吗？」——不是，退回。

### V3a — 骨架内核（壳无关，可与组合层 S0-S2 并行；agent 主场）

- 块数据模型：`{ id, 类型, 内容, state: flow|pinned, 世界坐标 x/y/w }`（设计文档 §3.1 真相层）
- **宿主侧块转译 v1**：现有 chat-stream（markdown + 工具事件）→ 语义块——**agent 层零改动**（R1-3 拍板的 staging）
- 画布引擎：有界平移缩放 / 视口虚拟化（数据全量、渲染窗口化）/ Pretext 测量接入
- 输入条 IME 安全性 spike（§6 风险项前置验证，学 WO-S0A 的做法：先证假设再施工）
- 落 `src-ui/src/paper/`，零 UI 依赖 + 无头测试（对齐 `agent/` 运行时纪律）
- 门禁：build + vitest + biome（不触 agent 面，无 convergence 义务）

### V3b — 壳装配（gate 于组合层 S1——串行拓扑下阶段 1 已完成，自然满足）

- 纸壳视图经组合层挂载（roster 行）；**块渲染器 = ctx service**——组合层第五贡献通道（D0 已预留此接口形状）
- 共居模式切换（先例：`v4-pro-minimal-ab-test-plan.md`）
- 走查弹验收 = R1-2 定义的「这就是纸」时刻跑通

### V4 — 视觉打磨环（短环 × N；**防发散协议**——本计划对「怎么都改不好」的结构性回答）

「Agent 前端怎么都改不好」的病理：agent 每轮重新发明（搜索空间不固定）× 用户每轮给混合反馈（信号不正交）= 随机游走。观测台当年靠很多轮随机搜索 + 人工评分磨到位——有效但极贵。V4 的任务是把随机搜索改造成**梯度下降**，五条规则：

1. **一环一维**：每环恰好一个视觉维度（间距节奏 / 字重层级 / 色彩浓度 / 对齐网格 / 投影深度 / 动效曲线 / 密度 / 留白）。反馈只谈本维，别维的发现记账本，不动手。
2. **对照式反馈（选择优于描述）**：agent 交付的永远是并排 A|B 截图（现状 vs 候选），用户选一个或说"都不对，方向 X"。**禁止"让它更好一点"这种无锚反馈**——那是随机游走的入口。
3. **品味账本**（`taste-ledger.md`，本目录）：每个决定一行——维度 / 上下文 / 选了什么 / 弃了什么 / 一句话为什么。作用：① 已判死的决定不复活（翻案需显式理由）② 新 agent 会话先读账本——**打磨知识不再随会话蒸发**。已付费的部分知识已在三处：`tokens.css`（观测台）、`paper-prototype*.html`、`ink-brass-*.html`——V2 时合并入账（实证：`--obs-brass: #c9a25c` 与白纸原型 `--brass-hi` **完全同值**，动效曲线同源，Fraunces 同款——品味 DNA 本就连续）。
4. **机械 gate 前置**：能用机器查的不过人眼——token 符合（禁 magic number）、间距只取刻度倍数、对比度阈值、字体栈符合。V2 后写成检查脚本进 CI。预计砍掉一半历史上的"不满意"——那半其实是契约违规，不是审美问题。
5. **止损规则（反"永不收敛"本体）**：每维最多 3 环；3 环内 A/B 都不过 → **不是执行问题，是契约问题** → 升级回 V2 改契约（该维 token/golden 错了），不继续磨实现。「更好但说不出哪维变好了」→ revert。V4 总环数预算开工时拍（建议 ≤20）；预算尽 → 接受现状进 V5——纸感来自材质与结构，不来自第 40 轮微调。

**截图回路（已验证可行）**：`src-tauri/src/cdp.rs` 有 cdp_screenshot，`tauri.conf.json` 已开 `--remote-debugging-port=9222`——agent 侧「渲染 → 截图 → read_image 对照金样」的机械回路存在，V4 开工首日钉一根验证刺（真跑通一次，学 WO-S0A 纪律）。

## 与组合层计划的排程（2026-08-20 拍板：三阶段串行，用户带宽优先）

- **阶段 1 = 组合层核心**（`../composition-architecture/` S0→S1→S2）：白纸不动工。用户角色 = 批 S1 设计件 + 绿灯放行，零深度参与。
- **阶段 2 = 白纸全程**（V0→V5，本计划主体）：agent 全部产能投前端；用户注意力集中于此——但均为短会话模式（访谈 / 选型 / 打磨判读），不是巨理解模式。V3b 的组合层 gate（S1）届时早已满足（串行拓扑下自然解）。
- **阶段 3 = 组合层收尾**（组合计划 S3→S4）：S3 面板迁移此时才有纸方向可依——先迁再定方向 = 给可能被纸废除的面做返工（组合计划 S3 协作纪律的必然推论）；纸壳的面板/命令贡献走组合层通道，不自建旁路。
- 例外（可选，零义务）：阶段 1 期间随时可做 V0 访谈——那是纯对话，不产生任何工程排程，做了只是让阶段 2 起步更快。

## 明确不做

- 不在原型阶段写生产代码；不让 agent 在生产代码里发明视觉（只许转录契约）
- 不做模型原生块输出（宿主侧转译先行；若证据显示需要模型原生块，那是 agent 层工程，**独立立项**走变更流程）
- 不在本计划内动 agent 运行时 / 冻结文件 / convergence 体系
