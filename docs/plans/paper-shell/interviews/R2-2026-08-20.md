## 拍板决定

### D-R2-1：钉住 = 拖出（基础手势）+ 原则「钉住 = 获得动手权」

- 基础手势确认：按住块拖到流旁空白处松手即钉住（物性浓度最高的动作不外包给控件；原型已演示此模式）。
- **原则级判断（用户原话：现在的工具卡"只能看不能上手动"问题很严重）**：钉住的块不是标本，是工作台实物——diff 可改、代码可就地编、plan 可勾。每种块渲染器除"渲染"外必须回答"用户能对它做什么"（可动手作集）——进 V2 契约待定项，工作量已由用户预判不小。
- 悬停钉（角落图钉按钮，系统自动落位）作为后加的快挡补充，非本决定一部分。

### D-R2-2：收回 = 按钮 + 确认提示

- 用户画面：钉住的块点按钮 → 弹确认 → 确认后块瞬移回原位（占位符处）。
- 设计依据（用户给出）：回原位是瞬移、去向不直观、不可逆 → 宁可多一拍确认，不做误触。此「宁可费手不失控感」哲学与 D-R2-1 拖出同性格，记录为交互性格基调。
- 注：与 R1 归档中「收回 = 拖回占位符」的原案并存——按钮为主通道，拖回可作为等价手势保留（走查弹验证哪种顺手，非本日决定）。

### D-R2-3：块 ↔ Agent 的信息流 = 内推外拉

- **内部改动 = 塞纸条（推）**：钉住块上的编辑随保存触发，以"纸条"注入该卡归属的 Agent 会话（用户已点明技术可行性：工具卡所属 Agent 可定位——归属链是现成的）。
- **外部改动 = 对账提示（拉）**：在软件外（编辑器等）改了同一文件/plan，**绝不唤醒**对应 Agent（用户判据：改一个文档唤醒一批历史 Agent 是灾难）。外部改动的唯一合法通道 = 用户下次主动接触该 Agent/卡片时的对账提示（卡片淡淡标出"文件在别处动过，差 N 行"，用户选择接受或忽略）。
- 架构原则：**推模型的合法性边界 = 软件内 + 归属链明确；归属链断裂处，只有拉。**
- **数据观拍板：钉住的块 = 活引用而非拷贝**（块与文件是同一实体的两个视图——存储层挂文件源，渲染层是视图）。连带消解"改到一半被读"的脏活：Agent 每轮世界观 = 对账时刻的干净快照，不存在中间态读取。

### D-R2-4：横向维度 = 开放用户主权区（不锁用途）

- 用户判断：甲（对照）/乙（并行流）/丙（留白）不互斥，均为未来真实落地的设计；且横轴留白**支持用户写写画画、贴自定义面板——插件化的大用武之地**（组合层四 service 注册"可贴上纸的东西"，横轴 = 插件生态的展示面）。
- 工程翻译为三条**消极决定**（锁"不做什么"）：
  1. 横轴不预设列结构（无网格/列管理特权逻辑）；
  2. 流锚独占窄带（对话流纵向轨道不横向蔓延）；
  3. 块的世界坐标是唯一真相（x/y 数据模型说了算，纸壳不保留摆放特权）。
- 甲/乙/丙/写画/贴面板 = 日后按需长出的 occupants，非今日预定的楼层平面图。走查弹对横轴的唯一要求：平移过去是一片可用空。
