## 拍板决定（四）

### D-R4-1：启动一等入口 = 纯会话优先

- 欢迎页 = 最近会话列表 +「新会话」，不再是选项目；目录绑定是会话**内**的动作（首次或随时）。
- 用户理由（定性）：「软件已经从以 engine 为主变成了以 Agent 为主，这里必须以『AGENT 软件』为设计语言来定性」。
- 零目录通用会话升格一等场景（用户在 Q2 明确：「开放一个『不挑选目录』的通用会话场景」）——纯问问题、不碰仓库。
- 推翻的现状：`view: 'welcome' | 'graph'` 二值 + 打开路径后第一动作 = 引擎全量分析 + 星图。

### D-R4-2：一会话一目录

- 绑定严格一对一；跨目录对照需求用只读 fs 工具满足。
- 用户理由：「没必要双根」。双根所有权是为低频需求买高频复杂度；真出现高频双仓工作流再升格（append-only 演进）。
- 与 D-R4-1 组合出三种会话形态：**零目录**（通用问询）/ **绑定目录**（编码工作）/ 跨目录只读（工具调用参数）。

### D-R4-3：图谱 = 后台预热 + 优雅降级

- 会话绑目录后图谱**后台**分析（不挡对话，秒进会话）；分析完成前 graph 工具返回「图谱分析中」诚实提示。
- 用户理由：「图谱是我 harness 的一部分，如果图谱 engine 不工作，很多 harness 成了摆设」——图谱不能砍也不能挡路，后台预热是唯一同时满足两者的解。
- 建议附带设置项「大仓库关后台分析」（施工时定）。

### D-R4-4：#9 与 V5 机制半同窗施工

- 翻转「家」与壳外化一批做掉：#9 结构翻转 + V5 机制半（bootShell 消费 composition + 纸壳 preset + 主视图切换）。
- 依据：ADR 自己说「翻转『家』与面板行化是同一件事的两面」；实查发现 bootShell 的 composition 参数从未被喂过（S4-1a 的 V5 双装配挂点只接了参数位没接数据流）——分开做的中间态「结构翻了但看不见」只能靠测试验证，无法人验。
- 工程量注：机制半是小工程（把已解析的 shell 域喂给已存在的参数位）；同窗的代价只是单批 commit 变大。
