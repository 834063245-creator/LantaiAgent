# R1 访谈记录 — 2026-08-20

> paper-shell V0 第一轮。性质：**归档记录，非新设计**（用户已立规矩：访谈产出只归档，纸面动作到此为止）。
> 方法论修正（本轮访谈最重要的元发现）：访谈目的不是「需求穷举」而是「排雷 + 定向」。用户原话——「我没法穷举所有场景，也没法穷举一个 Agent 软件需要提前决定多少东西」。回应：范式不靠穷举靠结构（不可逆少数派）+ 时间（真纸在手后迭代）+ 生态（渲染器插槽）；触屏手机 / 块协议 / DSH 四通道皆为先例。**穷举的负担从用户肩上卸下。**

## 拍板决定（三 + 一）

### D-R1-1：无限画布，废除「有界」

- 设计文档 §2.3 原案「纸有边界（有界，不跌入虚空）」**废除**。用户理由：有界 → 滚动条复活 → 违背纸的本意。
- 保留且升格的意图：**方位感**（原点标记 / 小地图 / 回原点快捷键 / 内容聚落）——无限画布不等于迷失。
- 技术注：Figma/Miro/tldraw 皆无限画布，成熟方案；方位感为设计义务而非结构负担。

### D-R1-2：Agent 产出默认 flow（流走），钉住是显式动作

- diff 卡 / tool result / plan 卡，不加干涉即随对话流走（设计文档 §2.2 两层所有权维持原案，本条为其默认值参数）。
- 数据模型注：`state: flow|pinned` 的默认值 = `flow`；宿主侧块转译层按此设定。

### D-R1-3：流锚 = 甲（向上生长）

- 新概念（用户访谈中原创提出）：**流锚（Stream Anchor）**——无限画布上「对话流从固定位置生长 + 方向」的锚点；无限画布上「上/下」非天生，需人为原点。
- 拍板：流向上生长，锚点在视口下缘，输入条固定视口底部（聊天/终端模式，非文档/卷轴模式）。
- 用户顾虑「人从上往下读」的消解：块内文本阅读方向与块列生长方向正交；列从下往上长、内容在块内从上往下读=聊天软件既有解。
- 决定性论据：Agent 输出高频续写，甲（终端感）适配机器喷涌，乙（文档感）适配人手写——纸的主体是前者。
- 可逆性注：流锚方向是实现层常数，V4 可翻；此处先定省掉 V1 双版本原型。

### D-R1-4：不可逆清单确认（五条 → 结构决定，非场景穷举）

用户确认的结构决定（其「技术落地提供不了意见」= 意图/技术分工，非未决）：

1. ~~纸的物理性之「有界」~~ → 由 D-R1-1 替换为「无限画布 + 方位感」
2. 两层所有权（默认值已定 D-R1-2）
3. 块协议（语义声明 + 可插拔渲染 + 一键展开）
4. 三层分离（DOM 干活不干政）
5. 世界坐标数据模型（`{id, 类型, state, x/y/w}`）

### D-R1-5：V1 视觉选型 = 不选边，主题化（2026-08-20 R1 收尾追加）

- 用户拍板：**白纸与深色是同一前端的一体两面，如两个主题**——V1「三向选一」的题目本身被拆除。
- 依据（既有实证）：观测台 tokens.css 与白纸原型 DNA 连续（`--obs-brass: #c9a25c` 与 `--brass-hi` 完全同值、同一 bezier 动效曲线、同款 Fraunces 衬线）——两套打样本就是同一视觉语言的昼夜两态。
- 连锁：V2 契约新增**主题机制**为正式交付物——token 双套（paper/dark 同构同义不同值）、运行时切换、跟随系统/手动、降级规则（no-bf 类环境约束的既有先例沿用）。块渲染器与骨架（V3a）必须主题无关：只消费语义 token，不写死颜色。
- 「墨黄铜」（ink-brass 方向）地位：不再是第三竞争者，并入**材质词汇表**（卷册/压纸/观测日志等质感元素可跨主题取用）。
- 品味账本同步：黄铜 accent / 动效曲线 / Fraunces 从「待合并」升格为「已定，跨主题恒定」。
