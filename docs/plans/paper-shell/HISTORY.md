## 本工程的性质（写给所有 agent——先校准预期，再谈管线）

**前端不是「一切定好就能做好」的转录流水线。** 定稿的契约（V2）只消灭「随机重掷」这一类失败；定稿之后仍有大量工作，形态是**高频率的沟通-修改-测试循环**：用户在真实使用中产生不满 → 描述不清的模糊反馈 → agent 猜测意图出候选 → 用户再判。这个循环是前端工程的**本体**，不是开销——观测台的现状就是非常多轮这样的循环磨出来的。本计划对它的态度：不消灭循环（消灭不了），而是给循环上纪律（V4 防发散协议：一环一维、对照反馈、账本、止损），让每轮循环都产生**留存的知识**（品味账本），而不是蒸发。

用户角色因此不是「短会话点缀」而是**共同创作者**——本工程的主要生产资料之一就是用户的判断力。给 agent 的排程含义：paper-shell 的推进节奏由用户对话带宽决定，agent 不催促、不擅自跳过人判环节、不用「契约已定」为由把循环压扁。

## 方法论：把「发明」压缩到最小，其余交给循环

| 任务类型 | Agent 能力 | 在管线中的合法位置 |
|---|---|---|
| 发明视觉设计（从构想产出新视觉） | ✗ 弱 | 只发生在 V1 一次性原型里；**人是唯一审美仲裁**（看 + 选） |
| 转录视觉（把已批准的视觉翻成代码/token） | ✓ 强 | V2 契约编码 + V3/V4 生产代码——**只许转录，不许现场发明** |
| 骨架工程（数据模型/布局数学/虚拟化/协议） | ✓ 强 | V3a 壳无关内核（纯逻辑，零视觉判断） |
| **共同创作循环（模糊反馈→候选→人判）** | **人机各半** | **V4 全程 + V5 之后的产品常态**——这是本工程的主体工作量 |

## V4 — 视觉打磨环（防发散协议）

「Agent 前端怎么都改不好」的病理：agent 每轮重新发明（搜索空间不固定）× 用户每轮给混合反馈（信号不正交）= 随机游走。五条规则把随机搜索改造成**梯度下降**：

1. **一环一维**：每环恰好一个视觉维度（间距节奏 / 字重层级 / 色彩浓度 / 对齐网格 / 投影深度 / 动效曲线 / 密度 / 留白）。反馈只谈本维，别维的发现记账本，不动手。
2. **对照式反馈（选择优于描述）**：agent 交付的永远是并排 A|B 截图（现状 vs 候选），用户选一个或说"都不对，方向 X"。**禁止"让它更好一点"这种无锚反馈**——那是随机游走的入口。
3. **品味账本**（`taste-ledger.md`）：每个决定一行——维度 / 上下文 / 选了什么 / 弃了什么 / 一句话为什么。已判死的决定不复活（翻案需显式理由）；新 agent 会话先读账本——**打磨知识不再随会话蒸发**。
4. **机械 gate 前置**：能用机器查的不过人眼——token 符合（禁 magic number）、间距只取刻度倍数、对比度阈值、字体栈符合。预计砍掉一半历史上的"不满意"——那半其实是契约违规，不是审美问题。
5. **止损规则**：每维最多 3 环；3 环内 A/B 都不过 → **不是执行问题，是契约问题** → 升级回改契约，不继续磨实现。「更好但说不出哪维变好了」→ revert。V4 总环数预算开工时拍（建议 ≤20）。

**截图回路**：`src-tauri/src/cdp.rs` 有 cdp_screenshot，`tauri.conf.json` 已开 `--remote-debugging-port=9222`——「渲染 → 截图 → read_image 对照金样」的机械回路存在且三段实测打通（第四段 read_image 依赖 vision 模型会话）。
