## 1. 方法：为什么用 min 不用 mean（本次实测的硬结论）

同一天、同一份代码、连跑两轮（A 轮宿主较静，B 轮宿主繁忙）：

| 指标 | A min | A mean | B min | B mean | mean 的 rme |
|---|---|---|---|---|---|
| 全卷挂载 standard（含 prompt 组装） | **4.29ms** | 8.84ms | **4.33ms** | 8.16ms | ±16% / ±16% |
| 全卷挂载 minimal | **3.99ms** | 7.44ms | **4.00ms** | 6.72ms | ±19% / ±16% |
| 全卷挂载 standard（prompt 预置） | **2.47ms** | 4.37ms | **2.28ms** | 8.13ms | ±17% / **±47%** |
| 建注册表 冷（新通道 apply） | **31.53ms** | 43.51ms | **70.96ms** | 99.77ms | ±20% / ±22% |
| 建注册表 热（族已缓存） | **6.22ms** | 12.27ms | **6.41ms** | 36.19ms | ±21% / **±67%** |
| resolveRoster（纯函数） | **2.3µs** | 3.7µs | **2.7µs** | 21.9µs | ±3% / **±64%** |
| effectiveComposition（cache 读） | **1.6µs** | 2.1µs | **1.6µs** | 5.4µs | ±3% / **±51%** |
| fs 派发 · owner 命中 | **11.6µs** | 15.8µs | **11.6µs** | 41.2µs | ±3% / **±53%** |
| fs 派发 · owner 缺席 | **11.6µs** | 17.8µs | **11.8µs** | 55.2µs | ±4% / **±53%** |
| seamScopeOf（裸查表） | **87ns** | 87ns | — | 105ns | ±4% / ±19% |

**min 两轮漂移 < 5%，mean 漂移 2–3×。** 根因 = 本机 DSH 宿主进程（`dsh web`，实测
1.5GB / 1700s+ CPU）自身常占一个核，长任务被抢占的概率随轮次波动。
⇒ **回归判据一律用 min（p75 次之）；mean 只作参考**，任何绝对 ms 门槛都不进红绿
（同判断见 `tests/perf-paper-pan.test.tsx` 头注）。

## 2. 基线数字（min 口径）

| 口径 | 值 | 说明 |
|---|---|---|
| **开一卷（热，含 prompt 组装）** | **≈ 4.3ms** | standard 4.29 / minimal 3.99 —— 用户在创作坞开一卷的挂载成本 |
| 其中 prompt 组装 | **≈ 1.8–2.1ms**（占 ~42–47%） | 含 `CLAUDE.md` 读取 / shell_env / 记忆段 / 技能目录（测试环境无 Tauri，RPC 失败即降级） |
| 装配面本身（prompt 预置） | ≈ 2.3–2.5ms | 注册表克隆 + blueprint capability 安装 + Agent 构造 |
| **冷装配（新通道 apply：建族 + 全量 schema 生成 + 注册 + 收敛）** | **≈ 31.5ms** | 应用启动 / 插件重装的代价 |
| 冷/热比 | **≈ 5.1×** | 建族 + schema 生成是一次性重活，热路径全靠实例缓存 |
| 组合解析 · `resolveRoster`（纯函数，零 patch） | ≈ 2.3µs | 每次组合解析的纯函数成本 |
| 组合解析 · `effectiveComposition`（cache 读） | ≈ 1.6µs | 生产热路径走这条 |
| **每卷常驻内存** | **≈ 0.80MB**（standard 0.79 / minimal 0.80） | 逐卷边际 `[-0.02 / 0.79 / 0.80]MB`（首卷读数被 GC 噪声吃掉，不可引用） |
| 三卷并存合计 | ≈ 1.57MB（standard） | 增量与卷数线性，无超线性面 |
| 调用期 · fs 派发全链（含 P2 的 owner 查表） | ≈ 11.6µs | owner 命中与缺席同价（11.6 vs 11.6）——查表是 Map.get，不构成分支成本 |
| 调用期 · 裸查表 `seamScopeOf` | ≈ 87ns | 占派发全链 **0.75%** ⇒ P2 的值注入没有把调用期拖慢 |

### 与 DSH 参照的口径差异（如实说明）

DSH 报「每卷 ~0.17MB（minimal）～ 1.31MB（standard）」，兰台实测**两个 preset 同量级
（≈0.80MB），没有 minimal/standard 的分化**。原因不是我们更省或更费，而是**架构差异**：
兰台的工具实例跨卷共享（`plugin-tool-rows` 的实例缓存 + 内层族缓存），每卷新增的是
Agent 实例 + 注册表骨架 + 会话日志；DSH 的 preset 是往 agent scope 挂 cordis 子树，
声明面本身按卷实例化。⇒ **兰台的每卷内存成本与组合大小基本无关**，这一点在 P3
（插件按需激活）里仍然成立——激活的是副作用，不是声明面。

## 3. 结构性事实（计数台钉住，与机器负载无关）

| # | 事实 | 机制 |
|---|---|---|
| ① | 行工厂每装配恰调一次/行 | `buildToolRegistry` 的 `Promise.all(rows.map(factory))` |
| ② | 同一贡献 factory 调两次 ⇒ **同名工具同一实例** | `contribution-helpers.ts` 的 `family ??= build(exec)`（内层族缓存） |
| ③ | 两次建表 ⇒ 同名工具同一实例 | `plugin-tool-rows.ts` 行级 `instanceCache`（外层，贡献 dispose 即清） |
| ④ | `noCache` 贡献每装配**重创**实例 | 同上，`c.noCache` 分支（P3 激活语义的现有旋钮） |
| ⑤ | 新通道 apply ⇒ 实例不同 | ②③ 的负向对照 |
| ⑥ | 组合解析 cache 读零拷贝；纯函数每次新对象但行序一致 | `preset-assembly` cache / `resolveRoster` 纯函数 |
| ⑦ | seam 作用域查表零拷贝 + 对称清理（幂等） | `seam-scope.ts`（P2） |

> **②③ 的破测实证（2026-09-15，值得记住）**：最初把 ② 写成「两次建表 ⇒ 同一实例」，
> 破测去掉内层 `??=` 竟然**照绿**——因为外层行级 `instanceCache` 兜住了。三层缓存是
> **独立**的：贡献 factory 内层族缓存 → 行级实例缓存 → `noCache` 绕过。要测内层必须
> **绕过行级缓存直接打贡献 factory**（② 现在就是这么写的，去掉内层缓存即红）。

## 4. P3 回归阈值（写回设计件 §3.7）

同机、同口径、**min 为判据**：

| 判据 | 阈值 | 当前基线 |
|---|---|---|
| 开一卷（热路径挂载） | 回归 **< +15%** | 4.3ms |
| 冷装配（新 apply：`requires`/`exclusive` 校验落点） | 回归 **< +20%** | 31.5ms |
| 每卷常驻内存 | **< +10%**（≤0.88MB） | 0.80MB |
| 三卷并存合计 | **≤1.75MB** | 1.57MB |
| 次卷边际内存 | 不得 > 1.5× 首卷稳态值（当前相等） | 0.79/0.80MB |
| 调用期 · 裸查表 | **< 1µs** 且不得引入每次调用的新分配 | 87ns |
| 调用期 · fs 派发全链 | 回归 **< +10%** | 11.6µs |

**这些阈值不进红绿**（宿主噪声），由 P3 施工者跑台子对表判断；结构性回归（如「每卷白建注册表」「内层缓存被摘」）由计数台红绿兜底。
