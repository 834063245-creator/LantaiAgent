# 工作区概念归属：从 engine 中心到 Agent 中心（方向已定）

> 日期：2026-08-20 · 状态：**Accepted（方向）——终局形态已由用户拍板；粒度细节留走查弹后，施工窗口 = 组合层 S2 完成后（不叠 diff）**
> 提出者：用户（2026-08-20 两次拍板：S2 落地期间首提「工作区从软件诞生第一天围绕 engine 设计，现在需要围绕 agent 设计；会话绑定工作区是正确方法」；同日定方向——见下节）
> 关联：两产品形式化（composition-boundaries ADR §4.1）——本文是该分界在「工作区」概念上的收尾

## 方向拍板（2026-08-20，用户）

> 原话要点：「如果软件重心迁移到 Agent 端，这个架构改变是必须要做的。未来没有图谱的位置——图谱会以一个非常内化的、某种后端『支柱』存在。它是我在 Agent 代码工作中大量 harness 工程的基石之一，不会退役，但会被内化。软件面向用户是一个纯粹的『新交互范式 Agent 软件』。」

**终局形态（锁定）：**

1. **软件用户面 = 纯粹的 Agent 软件**（新交互范式），图谱无常驻 UI 位置；
2. **图谱 = 内化的后端支柱**——不退役（harness 基石：graph 工具族 27 动作服务 Agent），但只以 Agent 的感官存在（engine 宿主无关的三消费者格局维持：TCP 9777 / dsh-bundle stdio MCP / 外部 MCP 客户端）；
3. **图谱视觉的完整内化含义**：从「常驻界面」降维为「对话中的物」——影响面图/依赖路径图等作为 Agent 产出的块出现（可钉住/对照/批注），而非 dock 面板与星图窗景。块协议 §3.2 可插拔渲染器天然承载；
4. **Workspace 翻转为 Agent 的家**：会话绑定工作区正式化；图谱分析降为会话属性（按需装载的资源），不再是打开软件的第一公民。

**三个连锁简化（对既有计划）：**

- 白纸 V5：终局从「共居后定」明确为「观测台整体退役，纸壳是唯一用户面」；R3 保留但只管过渡（共居期长度/退役判据），不再管终局；
- 组合层 S3：图谱类面板（星图/检查/约束等 dock 子女）走**退役路径**，不走行化迁移路径——S3 的迁移名单缩短为 Agent 产品域（settings/命令面板等跟随新壳的域）；
- scene/ 与 dock 图谱面板：终局 = 退役（认知层/图数据模型随 G 保留）。

## 问题（原始陈述，保留）

Workspace 入口层今天是 engine 中心的：open(path) 的第一公民是图谱分析/星图/检查面板，Agent 是树上顺带挂的果实。软件重心转向 Agent 产品（A）后，此概念归属需要倒置：Workspace 变为 Agent 的家，图谱降格为 Agent 的感官（可按会话装载的资源）。

## 现状证据（2026-08-20 实查）

- **数据层已是身份中心**：`.hologram/agents/{agentId}/`、`taskboard/{sessionId}.json`、`goals/{id}/`——Agent 持久化按身份组织，不按工作区。
- **无图谱路径已有雏形**：`createAgentOnlyWorkspace`（仅 Agent 模式占位工作区，永不激活）+ `createPlaceholderAgent`。
- **解耦前置已定**：R2 活引用（块挂文件源不挂工作区）+ 组合层 S1 行表（装配不依赖 Workspace 单例）——翻转的两块地基已铺。
- **engine 侧本来无绑**：图谱机器（G）以 stdio MCP / TCP 服务外部消费者，本就不持有 Workspace 概念。

## 剩余子题（粒度细节，走查弹后定——方向已不需要它们）

1. 跨目录会话的形态（图谱为会话属性后）；
2. 会话 ↔ 工作区绑定粒度（一对一 / 一会话多目录）；
3. 无图谱启动升格一等入口（欢迎页 = 新会话而非选项目？）；
4. 共居过渡期长度与观测台退役判据（R3）。

## 纪律

方向已定；设计未做。施工窗口 = 组合层 S2 完成后、与 S3 同窗协同（翻转「家」与面板行化是同一件事的两面）；在此之前不动 workspace.ts。
